## Recommended next work

The next phase is adoption evidence, not another broad feature expansion:

1. Use `docs/LAUNCH_KIT.md` for one approved launch post and primary image.
2. Recruit five external installers and record first generation, second automatic update, setup time, friction, and showcase permission.
3. Keep a lightweight weekly adoption snapshot before deciding on Discussions, GitHub Pages, or ongoing SEO content.
4. Accumulate historical language snapshots before designing a timeline renderer.
5. If token statistics remain interesting, follow `docs/CODE_TOKEN_STATISTICS_RESEARCH.md` with a non-releasing benchmark prototype first.

Still out of scope by product decision:

- automatic AI-authored-code detection;
- a hosted RepoPalette backend or default PAT requirement;
- GitHub App packaging without evidence that its added service and permission cost is justified;
- narrative animal, mascot, or developer-totem output as a current product promise.
